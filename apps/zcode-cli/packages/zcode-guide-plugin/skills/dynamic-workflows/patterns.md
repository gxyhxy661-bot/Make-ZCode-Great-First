# 动态工作流模式（Patterns）

从既有工作流里沉淀的几种可复用结构。示例为示意稿，API 以
`@zcode/dynamic-workflow` 当前沿为准。

## 模式 1：收集 → 处理 → 结算

最通用的三段式。收集阶段只做 world-run 读取；处理阶段做转换；结算阶段用
report 输出。适用面最广，也是排查问题的基线结构。

## 模式 2：清单驱动的扇出（fan-out）

- 收集阶段产出一组行（文件、用例、目标主机…）；
- 处理阶段对每行独立处理，行间无共享状态 → 引擎可安全并行；
- 每行写回自己的状态字段，结算阶段只汇总失败行。
- 关键点：**行独立是并行安全的前提**，处理逻辑不要读其他行的状态。

## 模式 3：门禁式验证流水线

多个验证阶段串联，每个阶段产出 verdict 行；任何阶段出现失败行即短路，
后续阶段以「上游失败」占位行结算。适合 CI 前置检查这类"一票否决"任务。

## 模式 4：幂等重放

- 产物行带内容哈希（引擎侧 `hash` 语义）；
- 重放时跳过哈希未变的行，只重算受影响的输入；
- 配合引擎的 imported-cache 语义，可以低成本重跑长流水线。

## 模式 5：人审断点

在阶段边界插入 report 行并暂停推进，等用户确认后再继续。
适合代价高的写操作（批量删除、外部提交）——把"确认"做成工作流的显式阶段，
而不是靠 Agent 临场判断。

## 选型速查

| 任务形态 | 模式 |
| --- | --- |
| 只读分析、出报告 | 模式 1 |
| 批量同类操作 | 模式 2 |
| 多关卡验证 | 模式 3 |
| 长流水线反复重跑 | 模式 4 |
| 高危写操作 | 模式 5 |
